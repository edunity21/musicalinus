# MUSICALINUS 제작소 — 학급 뮤지컬 공동 창작 플랫폼

승평중학교 음악과 · 중학교 3학년 · 2학기 WE 프로젝트
**여섯 모둠이 각각 한 막(대사 + 넘버 하나)을 맡아 학급 뮤지컬 한 편을 완성합니다.**

---

## 이 플랫폼이 하는 일

| | |
| --- | --- |
| 학급 하나 | 뮤지컬 한 편 (6막 6넘버) · **여섯 모둠** |
| 모둠 하나 | 한 막 + 그 막의 넘버 하나 · **다섯 명** (30명 학급 = 6 × 5) |
| 학생 한 명 | **배역 하나**(그 인물의 대사를 씀) + **제작 역할 하나**(담당 칸을 채움) |

다섯 사람이 서로 다른 칸을 채우면 **서버가 하나의 막으로 합쳐 줍니다.**
같은 칸을 두 사람이 고쳐 서로의 글을 지우는 일이 생기지 않습니다.

### 제작 역할과 담당 칸

| 역할 | 채우는 칸 |
| --- | --- |
| 대본 리더 | 막 제목 · 시간대 · 무대 배경 · 장면 이름 · 한 줄 줄거리 · **지문** · 대사 순서 |
| 작사 리더 | 넘버 제목 · **가사**(파트 배분 포함) |
| 작곡 리더 | **Suno 프롬프트 네 칸** (Genre · Mood · Instruments · Vocal Structure) |
| 편곡 리더 | 넘버 구성(전주–벌스–후렴) · 데모 A/B 비교와 선택 이유 |
| 발표 리더 | 배역 배정 · 연출 노트 · **최종 제출** |
| 공동 대본 *(여섯 번째 자리 — 다섯 자리가 다 찼을 때만 열림)* | 대본 리더와 함께 지문·대사 |

**대사는 자기가 맡은 배역의 줄만** 고칠 수 있습니다. 남의 줄은 읽기만 됩니다.
그래서 "한 명이 다 하고 나머지는 구경"이 구조적으로 막힙니다.

### 파일 제출 — [파일] 탭

글만 쓰는 것이 아니라 **만든 것을 그 자리에서 냅니다.** 파일은 **모둠원 누구나** 올릴 수 있습니다.

| 무엇 | 어떻게 | 크기 | 어디에 쌓이나 |
| --- | --- | --- | --- |
| **음원** (Suno mp3·m4a·wav) | 플랫폼에서 바로 올림 | 한 파일 18MB · 모둠당 12개 | 교사 드라이브 `MUSICALINUS 제출 / 3-3 / 1모둠` |
| **그림** (포스터·무대 스케치·pdf) | 플랫폼에서 바로 올림 | 위와 같음 | 위와 같음 |
| **동영상** (리릭 비디오·편집 영상·공연 녹화) | [영상 내기] → 새 창 구글 폼 | 파일당 1GB | 폼이 만든 드라이브 폴더 |

- 올린 음원은 **그 자리에서 들어 볼 수 있고**, 그림은 그 자리에서 보입니다.
- 지우기는 **올린 사람과 발표 리더**만 됩니다. 드라이브에서도 휴지통으로 갑니다.
- 동영상만 새 창인 이유: 구글이 파일 업로드 문항이 있는 폼을 화면 안에 끼워 넣지 못하게 막았습니다.
  대신 학급·모둠·학번·이름이 미리 채워져 나가므로 학생은 파일만 고르면 됩니다.
- 누가 냈는지는 학생 화면과 교사 화면 양쪽에 그대로 보입니다.

## 파일 구성

| 파일 | 하는 일 | 고칠 일 |
| --- | --- | --- |
| `index.html` | **학생용 주소** | 없음 |
| `teacher.html` | **교사용(수업자용) 주소** | 없음 |
| `config.js` | 서버 주소 · 클라이언트 ID · **영상 폼** · 학급 목록 | **★ 반드시 고침** |
| `story.js` | 여섯 막의 뼈대 · 등장인물 · 역할표 | 작품을 바꾸려면 |
| `style.css` | 두 화면이 함께 쓰는 디자인 | 색을 바꾸려면 맨 아래 15번 구역 |
| `common.js` | 서버 통신 · 구글 로그인 · 저장소 | 없음 |
| `app.js` | 학생 화면 동작 | 없음 |
| `teacher.js` | 교사 화면 동작 | 수업 시간 길이만 |
| `Code.gs` | 구글 서버 (Apps Script) | 이미 채워 둠 (교사 계정만 확인) |

> `common.js` 는 **음악 산업 탐구(musicjob)** 에서 쓰던 것을 그대로 물려받았습니다.
> 로그인·명렬표·수업 통제 방식이 같으므로 학생들이 새로 배울 것이 없습니다.

### 색 — 학생은 민트 그린, 교사는 하늘색

musicjob의 검은 화면과 확실히 구분되도록 **밝은 파스텔**로 만들었습니다.
교실 프로젝터와 창가 자리에서 훨씬 잘 보입니다.

| | 바탕 | 포인트 |
| --- | --- | --- |
| 학생 화면 | 옅은 민트 `#EEF6F2` | 깊은 민트 그린 `#0B7A4E` |
| 교사 화면 | 옅은 하늘 `#ECF4FA` | 하늘색 `#0B6FA4` |

색을 바꾸려면 `style.css` **맨 아래 15번 구역**의 `:root` 와 `body.teacher` 두 덩어리만
고치면 전체가 따라 바뀝니다. 예전 검은 화면으로 되돌리려면 15번 구역을 통째로 지우면 됩니다.
글자와 바탕의 명도 대비는 모두 4.5:1 이상으로 맞춰 두었습니다.

## 설치 — 일곱 단계

```
1단계  구글 클라이언트 ID  ← musicjob 것을 그대로 씁니다 (새로 안 만들어도 됨)
2단계  스프레드시트 + Apps Script                → /exec 주소를 받음
3단계  영상 제출용 구글 폼 만들기                 → 폼 주소와 entry 번호를 받음
4단계  config.js 고치기
5단계  깃허브에 올리기                            → 두 개의 주소가 생김
6단계  명렬표 넣기
7단계  모둠 편성 (학생이 스스로 / 교사가 지정)
8단계  수업 전 점검
```

### 1단계 · 구글 클라이언트 ID

**새로 만들지 않아도 됩니다.** 음악 산업 탐구에서 쓰던 클라이언트 ID를 그대로 씁니다.
승인된 자바스크립트 원본이 `https://edunity21.github.io` 로 되어 있으면 경로가 달라도 통합니다.
(`config.js` 에 이미 그 값이 들어 있습니다.)

**[확인]** 학생 화면에서 구글 로그인 단추를 눌렀을 때 계정 선택 창이 뜨면 됩니다.
`400 오류: invalid_client` 가 뜨면 승인된 원본에 `https://edunity21.github.io` 가 빠진 것입니다.

### 2단계 · 스프레드시트와 서버

1. <https://sheets.new> 로 새 스프레드시트를 만들고 이름을 `뮤지컬_수집` 으로 바꿉니다.
2. **파일 → 설정 → 시간대**를 `(GMT+09:00) 서울` 로 맞춥니다. ← **꼭 하세요.**
3. **확장 프로그램 → Apps Script** 를 엽니다.
4. `Code.gs` 안의 내용을 전부 지우고, 이 폴더의 `Code.gs` 를 통째로 붙여 넣습니다.
5. 맨 위 ★ 표시된 세 줄을 확인합니다.

   → **이미 채워 두었습니다.** 교사 계정이 `onixzone@ai.jne.kr` 이 맞는지만 확인하세요.

   ```javascript
   const CLIENT_ID      = '432757752918-...apps.googleusercontent.com';  // musicjob 것 재사용
   const TEACHERS       = ['onixzone@ai.jne.kr'];
   const ALLOWED_DOMAIN = 'ai.jne.kr';
   ```

6. 저장(💾) → 함수 목록에서 **`setup`** 을 고르고 **실행**
   - 권한 요청 → 검토 → 계정 선택 → 고급 → *(안전하지 않은 페이지로 이동)* → 허용
   - 시트 여섯 개(`설정` `명렬표` `모둠원` `모둠작업` `제출` `로그`)가 생깁니다.
7. 오른쪽 위 **배포 → 새 배포** → 톱니바퀴 → **웹 앱**
   - 설명 `v1` · **다음 사용자로 실행: 나** · **액세스 권한: 모든 사용자** ← 안 하면 학생이 못 씁니다
   - 배포 → **웹 앱 URL**(`.../exec`)을 복사

**[확인]** 그 주소를 브라우저에 붙여 넣어
`{"ok":true,"version":"server v1.0.0 (2026-09-07)","now":"..."}` 가 보이면 성공입니다.

### 3단계 · 영상 제출용 구글 폼 만들기

동영상은 파일이 커서(보통 100~400MB) 이 플랫폼이 직접 받지 못합니다. 구글 폼으로 받습니다.
**음원과 그림만 쓰실 거면 이 단계를 건너뛰어도 됩니다.** 그러면 [파일] 탭에서 영상 부분만 사라집니다.

> 구글은 **파일 업로드 문항이 있는 폼을 화면 안에 끼워 넣지 못하게 막아 두었습니다.**
> 그래서 [영상 내기] 단추를 누르면 새 창으로 열립니다. 대신 학급·모둠·학번·이름은
> 미리 채워져 있어 학생은 **파일만 고르고 [제출]** 을 누르면 됩니다.

**① 폼 만들기** — <https://forms.new> · 제목 `MUSICALINUS 영상 제출`

**② 문항 다섯 개를 이 순서로** (제목의 낱말이 중요합니다. 서버가 낱말로 열을 찾습니다)

| 문항 제목 | 종류 | 설정 |
| --- | --- | --- |
| `학급` | 단답형 | 필수 |
| `모둠` | 단답형 | 필수 |
| `학번` | 단답형 | 필수 |
| `이름` | 단답형 | 필수 |
| `영상 파일` | **파일 업로드** | 특정 형식만 → **동영상** · 최대 1개 · 최대 크기 **1GB** |

> 제목에 `학급` `모둠` `학번` `이름` 이 들어가야 하고, 파일 문항 제목에는
> `영상` `파일` `업로드` 중 하나가 들어가야 합니다. 앞뒤에 다른 말이 붙는 것은 괜찮습니다.

**③ 응답을 스프레드시트에 연결** — 이것을 해야 누가 냈는지 화면에 뜹니다.

`응답` 탭 → 초록색 시트 아이콘 → **[기존 스프레드시트 선택]** → **`뮤지컬_수집`** → [선택]
→ `뮤지컬_수집` 에 **`폼 응답 1`** 시트가 생깁니다.

**④ entry 번호 네 개 찾기**

폼 편집 화면 오른쪽 위 **⋮ → [미리채운 링크 가져오기]**
→ 네 칸에 각각 `AAA` `BBB` `CCC` `DDD` 를 넣고 → 아래 **[링크 가져오기]** → **[링크 복사]**

복사한 주소가 이렇게 생겼습니다.

```
https://docs.google.com/forms/d/e/FAIpQLSf..../viewform?usp=pp_url
   &entry.1111111=AAA        ← 학급
   &entry.2222222=BBB        ← 모둠
   &entry.3333333=CCC        ← 학번
   &entry.4444444=DDD        ← 이름
```

`AAA`~`DDD` 를 보고 어느 번호가 어느 문항인지 짝지으면 됩니다.

**⑤ 폼 주소 받기** — 폼 오른쪽 위 **[보내기]** → 🔗 링크 아이콘 → 주소 복사
(`.../viewform` 으로 끝나는 것)

**[확인]** 폼을 새 창에서 열어 파일을 하나 올려 보세요.
`뮤지컬_수집` 의 `폼 응답 1` 시트에 한 줄이 쌓이면 성공입니다. 그 줄은 나중에 지우세요.

교사 주소는 탭 이름이 `🎛 MUSICALINUS 수업자용` 으로 다르게 나옵니다.

### 6단계 · 명렬표

교사용 → **명렬표** 탭 → 엑셀에서 **학번 / 이름 / 비밀번호** 세 칸을 복사해 붙여 넣고 [명렬표에 넣기].

```
3301	홍길동	a1b2c3
3302	김철수	d4e5f6
```

- 학번은 **네 자리**. 두 번째 자리로 반을 판별합니다. (`3301` → 3학년 3반 1번)
- 이미 있는 학번은 **이름·비밀번호만** 바뀌고 계정 고정은 유지됩니다.
- 붙여 넣기 전에 [확인해 보기] 를 누르면 잘못된 줄과 겹치는 학번을 먼저 걸러 냅니다.

### 7단계 · 모둠 편성

**두 가지 방법이 있습니다. 섞어 써도 됩니다.**

| | 학생이 스스로 | 교사가 지정 |
| --- | --- | --- |
| 언제 | 첫 차시, 모둠을 이미 정해 두었을 때 | 결시자·전학생·다툼이 있을 때 |
| 어떻게 | 로그인 뒤 자리 고르기 화면에서 모둠·제작 역할·배역을 고름 | 교사용 → 모둠 현황 → 이름을 눌러 고침 |
| 겹치면 | **먼저 고른 사람이 임자.** 남은 자리만 눌립니다 | 겹쳐도 강제로 넣을 수 있습니다 |

**한 모둠은 다섯 명입니다.** 제작 역할이 다섯 개(대본·작사·작곡·편곡·발표)이고,
학생 화면에 `이 모둠에 남은 자리 n개 · 정원 5명` 이 함께 뜹니다.
학급이 30명이면 정확히 6모둠 × 5명으로 떨어집니다.

> **31명 이상인 학급은?** 다섯 자리가 다 찬 모둠에만 **여섯 번째 자리(공동 대본)** 가 저절로 열립니다.
> 그 전에는 점선으로 잠겨 있어 학생이 누를 수 없습니다. 인원 기준은 `config.js` 의
> `MEMBERS_PER_GROUP` 에 적혀 있습니다.

> 첫 차시에 칠판에 **모둠 번호 = 막 번호**라고 적어 주세요.
> 1모둠은 아침(1막), 6모둠은 피날레(6막)입니다.

### 8단계 · 수업 전 점검 (5분 전)

1. 교사용 → **수업 통제** 탭
2. 표에 학급 아홉 줄이 보이고 전부 `닫힘` 이면 정상
3. 시험 삼아 아무 학급이나 [수업만] → `수업 중` 으로 바뀌는지 확인 → [종료]

| 닫히면 학생은 | 화면에 들어오지 못함 | 들어와 쓸 수는 있으나 못 냄 |
| 닫히면 서버 저장은 | **멈춤** (기기에는 남음) | 계속됨 |
| 언제 여나 | 수업 시작할 때 | 마지막 차시에 |

**입장이 닫히면 제출도 자동으로 닫힙니다.** 반대는 아닙니다.
집에서 이어 쓴 내용은 서버에 남지 않으므로 **과제형 수행평가 금지** 요건을 충족합니다.

시간 길이는 `teacher.js` 맨 위 두 줄에서 바꿉니다.

```javascript
const LESSON_MINUTES = 50;   // [수업만] · [수업+제출 열기] 가 여는 시간
const SUBMIT_MINUTES = 25;   // [제출 열기] 가 여는 시간
```

| 시점 | 누를 단추 |

| 시점 | 누를 단추 |

교사용 → **합본 대본** 탭 → 학급 고르고 [불러오기] → [인쇄 / PDF]

**모둠 현황** 탭의 `영상 낸 모둠` 숫자로 확인하세요.

### 결시자 재작성
1. **손으로 세밀하게 고치기** 를 펼칩니다
2. 그 학급 줄의 `다시 내기` 를 켜고 [바뀐 설정 저장]
3. **[수업+제출 열기]**
4. 끝나면 `다시 내기` 를 되돌립니다

한 모둠만 풀어 주려면 **모둠 현황** 탭에서 그 모둠의 [다시 열어 주기] 를 누르면 됩니다.

## 세부 동작

### 학생 화면이 지키는 것
- **자동 저장** — 글자를 칠 때마다 기기에 저장, 서버에는 2초 모았다가 보냅니다. 탭을 닫을 때 한 번 더.
- **내 칸만 보냅니다** — 담당이 아닌 칸은 아예 서버로 가지 않아 남의 글을 덮을 수 없습니다.
- **모둠원 것 받아오기** — 12초마다 자동으로, 또는 단추를 눌러 즉시. 내가 지금 치고 있는 칸은 건드리지 않습니다.
- **기기가 고장 나도** — 다른 태블릿에서 같은 계정으로 들어오면 서버에 있는 모둠 문서를 그대로 받습니다.
- **시계 조작 불가** — 열림/마감 판단은 전부 서버가 합니다.

### 서버가 거부하는 경우 (모두 `로그` 시트에 남습니다)
| 사유 | 언제 |
| --- | --- |
| `DOMAIN_DENIED` | `@ai.jne.kr` 이 아닌 계정 |
| `NOT_IN_ROSTER` | 명렬표에 없는 학번 |
| `NAME_MISMATCH` | 학번과 이름이 안 맞음 |
| `WRONG_PASSWORD` | 비밀번호 틀림 (5번 틀리면 5분 잠금) |
| `ACCOUNT_MISMATCH` / `DUPLICATE_ACCOUNT` | 남의 학번으로 들어오려 함 |
| `ENTRY_CLOSED` / `ENTRY_BEFORE` / `ENTRY_AFTER` | 수업이 열려 있지 않음 |
| `BEFORE_OPEN` / `AFTER_CLOSE` / `CLOSED` | 제출 시간이 아님 |
| `ALREADY_SUBMITTED` | 이미 냈는데 다시 내기가 꺼져 있음 |
| `JOB_TAKEN` / `ROLE_TAKEN` | 그 자리는 이미 다른 모둠원이 맡음 |
| `NOT_LEADER` | 발표 리더가 아닌 사람이 제출을 누름 |
| `INCOMPLETE` | 완성 검사를 통과하지 못함 |

### 시트 구성
| 시트 | 내용 |
| --- | --- |
| `설정` | 학급별 입장·제출 허용/시각/공지. 학급 칸이 비면 `전체` 줄을 따릅니다. |
| `명렬표` | 학번·이름·반·비밀번호·연결된 계정·최근 접속 |
| `모둠원` | 학번·이름·반·모둠·제작 역할·배역 |

| `제출파일` | 플랫폼에서 올린 음원·그림 한 개가 한 줄. 드라이브 주소가 들어 있어 눌러서 바로 듣습니다. |

| `로그` | 거부·성공 기록 |

## 문제가 생기면

| 증상 | 원인과 해결 |
| --- | --- |
| 로그인 단추가 안 보임 | 클라이언트 ID 오타. `config.js` 확인. |
| `400: invalid_client` | 승인된 자바스크립트 원본에 `https://edunity21.github.io` 없음. |
| 저장은 되는데 서버 저장 실패 | `/exec` 주소 오타, 또는 배포 액세스 권한이 `모든 사용자`가 아님. |
| 코드를 고쳤는데 그대로임 | Apps Script **[배포 관리] → 연필 → 새 버전**을 안 눌렀음. |
| 시간이 이상함 | 스프레드시트 시간대가 서울이 아님. |
| 학생이 로그인이 안 됨 | 그 학급의 **입장**이 닫혀 있음. [수업만]을 누르세요. |
| 제출이 안 열림 | 입장이 열려 있는지 먼저 보세요. |
| "그 자리는 이미 찼습니다" | 다른 학생이 먼저 골랐습니다. 모둠 현황에서 교사가 바꿔 줄 수 있습니다. |
| 모둠원이 쓴 게 안 보임 | [모둠원 것 받아오기] 를 누르세요. 자동은 12초 간격입니다. |
| 내용이 너무 길다고 나옴 | 한 막의 JSON 이 48,000자를 넘었습니다. 대사를 줄이거나 나누세요. |
| 파일이 너무 크다고 나옴 | 18MB가 한계입니다. 동영상이면 [영상 내기]로 내세요. mp3 는 Suno에서 다시 받으면 보통 5MB 안쪽입니다. |
| "드라이브에 넣지 못했습니다" | 교사 드라이브 용량이 찼거나 권한이 풀렸습니다. Apps Script를 **다시 배포(새 버전)** 하고 권한을 다시 허용하세요. |
| 올린 음원이 재생되지 않음 | 학생이 `@ai.jne.kr` 로 로그인돼 있어야 합니다. 다른 계정이면 [새 창]으로 열어 보세요. |
| [영상 내기] 를 눌러도 창이 안 뜸 | 브라우저가 팝업을 막았습니다. 주소창 오른쪽 끝 아이콘 → 허용. |
| 영상을 냈는데 화면에 안 뜸 | 폼 응답이 `뮤지컬_수집` 에 연결돼 있는지, 문항 제목에 `학급` `모둠` 이 들어 있는지 확인하세요. |

### 버전 표시가 있는 곳
- 학생 화면: 로그인 화면 아래 + 콘솔(F12)
- 교사 화면: 로그인 화면 아래 + 상단 `server v1.0.0 · 시트 연결됨`
- 서버: `/exec` 주소를 직접 열기, 또는 스프레드시트 메뉴 `뮤지컬 제작소 → 버전 확인`

## 작품을 바꾸고 싶을 때

`story.js` 하나만 고치면 학생·교사 화면이 같이 바뀝니다.

| 무엇 | 어디 |
| --- | --- |
| 작품 제목·부제 | `SHOW` |
| 등장인물 | `CAST` — `key` 는 저장에 쓰는 이름이라 **이미 쓴 대사가 있으면 바꾸지 마세요** |
| 막의 시간대·장소·질문 | `ACTS` |
| 넘버 장르 보기 | `ACTS[n].numberHint` |
| 제작 역할 | `JOBS` 와 `FIELD_OWNER` — **`Code.gs` 의 `FIELD_OWNER` 도 똑같이** 고쳐야 합니다 |
| 완성 검사 기준 | `Code.gs` 의 `checkWork_` 와 `app.js` 의 `checkState` — **두 곳** |

모둠(=막) 개수를 바꾸려면 `config.js` 의 `GROUP_COUNT`, `Code.gs` 의 `GROUP_COUNT`,
`story.js` 의 `ACTS` 길이 **세 곳**을 함께 맞춰야 합니다.

## 알아 두실 점

- **구글 로그인 스크립트만** `accounts.google.com` 에서 불러옵니다. 나머지(폰트)는 `cdn.jsdelivr.net` 만 씁니다.
  외부 UI 라이브러리는 없습니다.
- **Apps Script 실행 할당량** — 한 학급 30명이 20초마다 상태 확인, 12초마다 모둠 동기화를 합니다.
  9개 학급을 하루에 몰아서 하지 않는 한 여유롭습니다. 걱정되면 `config.js` 의
  `POLL_SECONDS` 를 30~40, `SYNC_SECONDS` 를 20~30으로 올리세요.
- 학생 화면은 **가로 360px 스마트폰**부터 맞췄고, 터치 영역은 44px 이상입니다.
- **올린 파일은 교사 드라이브에 쌓입니다.** 학생 계정 용량을 쓰지 않습니다.
  학교 도메인 안에서 링크로 볼 수 있게 공유되므로 모둠원끼리 서로 들어 볼 수 있습니다.
  한 학급 여섯 모둠이 mp3 두 개씩 올리면 학급당 약 60MB, 아홉 학급이면 500MB 남짓입니다.
- **동영상은 교사 드라이브를 쓰지 않습니다.** 구글 폼이 만든 별도 폴더에 쌓입니다.
- **예시 대본은 뼈대일 뿐입니다.** `story.js` 의 `sample` 은 학생 화면에서 접힌 [예시 보기] 안에만
  나타납니다. "이 정도 결로 쓴다"를 보여 주려는 것이지 베끼라는 것이 아닙니다.
